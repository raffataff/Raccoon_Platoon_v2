# Plan: Fix Top Border Enemy Spawning Issue

## Problem
The top border uses the `fence_barbed_straight_long` sprite with a collision box that only covers the bottom ~11% of the sprite (offsetY: 8%, height: 3%). This creates a gap at the top of the screen where enemies can spawn but shouldn't. The bottom border works correctly because the collision box aligns with ground level.

## Solution
Add a keepout zone for the top border that prevents enemy spawning in the area above the collision box. The bottom border behavior remains unchanged.

## Changes

### File: `js/levelGenerator.js`

**Location: After line 464** (after `extraKeepOutZones.push(this.level.effectivePlayerSpawnZone);`)

Add a keepout zone for the top border:

```javascript
// Keepout zone for top border - prevents spawning in the gap between 
// sprite top and collision box (collision box is at bottom of fence sprite)
extraKeepOutZones.push({
    x: 0,
    y: 0,
    width: worldWidth,
    height: topBottomBorderHeight
});
```

**Rationale:**
- The keepout zone spans from y=0 to `topBottomBorderHeight` (the full visual height of the fence sprite)
- This prevents any enemy spawning in the top border area
- The bottom border is NOT affected - enemies can still spawn near it (as intended)
- The existing collision box on both borders remains unchanged for movement blocking and cover

## Why This Approach
1. **Minimal change** - Only adds 5 lines of code
2. **Clean separation** - Uses the existing keepout zone system
3. **Non-breaking** - Bottom border behavior unchanged
4. **Targeted** - Solves only the top border spawning issue

## Alternative Considered
Using the full sprite collision for the top border instead of a keepout zone was considered, but rejected because:
- Would require modifying the border obstacle creation logic
- Would change how collision works for the top border vs bottom border
- Keepout zone approach is cleaner and more maintainable
